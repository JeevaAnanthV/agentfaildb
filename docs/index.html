The finding · success by task type

Failure is about what the agents are asked to do, not how "hard" it's labeled. Open-ended reasoning and planning pass easily; the correctness-critical tasks — writing code, analysing data — are where local 8B multi-agent systems actually fall down.

How to read this — honestly

  • Detectors are heuristic signals, not validated labels. There's no human-annotated ground truth here, so no detection accuracy (precision / recall / Kappa) is claimed.
  • Success is graded by a local 8B judge. That inflates and flattens pass rates — treat every number as directional, not authoritative.
  • One small model. An 8B model's failure behaviour needn't generalize to frontier models.
  • The validated reference is MAST (Cemri et al., “Why Do Multi-Agent LLM Systems Fail?”, NeurIPS 2025) — 14 failure modes, 7 frameworks, human ground truth. This project is a fully-local reproduction/extension, not a replacement.

What it's genuinely good for: a complete multi-agent failure sweep that normally needs an API budget, run for free on hardware you already own — and a concrete read on where small-model agents break (correctness-critical work), not just that they do.
